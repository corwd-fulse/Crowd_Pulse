# 범용 장소와 촬영 세션

기존 지도·ROI 승인·YOLO/ByteTrack·Optical Flow·Worker·분석 결과·2D/3D를 재사용한다.
새 모델을 학습하거나 기존 모델 파일을 수정하지 않는다. 특정 행사, 날짜, 주소, 카메라 대수는 기본 설정에 넣지 않는다.

## 사용 방법

1. 프런트엔드 `/sessions`의 **새 관제 장소 등록**에서 이름·유형·주소를 등록한다.
2. **이 장소의 관제 지도 열기**에서 평면도, 관측 구역, 출입구·시설 마커, 카메라 위치·범위와 통로를 설정한다.
   **구역 연결 · 보행 통로**에서는 영상 없이 일반 보행 통로·출입구·계단·병목 연결을 등록한다.
   지도에서 회색 점선으로 표시하며 관측 흐름이나 미래 경로로 해석하지 않는다.
   영상이 없어도 카메라를 등록할 수 있다. 비활성 카메라는 추정에서 제외된다.
   기존 지도는 `/dashboard`의 `main`에 남으며, 새 장소는 `/dashboard?venue=<venue_id>`로 구분된다.
3. `/sessions`에서 장소를 선택하고 세션 이름, 시간대가 포함된 시작·종료 시각, 계획/실제 촬영,
   일반/행사 여부·단계, 조명, 환경을 입력한다. 평일/주말은 날짜에서 계산한다.
   공휴일은 근거를 입력하여 분류하며, 모르면 null이다. 여러 날짜는 일별 달력 정보를 제공한다.
4. **여러 영상 업로드**로 파일을 순차 업로드하거나 **기존 영상 연결**에서 영상 ID를 입력한다.
   카메라 ID는 장소 안에서 지속적으로 사용할 식별자를 입력한다. 원본 영상은 기존 스트리밍 API로 재생한다.
5. ROI와 분석 요청은 기존 `/videos`에서 수행한다. Worker를 자동 실행하거나 재시작하지 않는다.
   분석 완료 후 세션에서 파일명·완료 분석·원본 ROI를 선택하고 지도 구역과 예측 대상 구역을 연결하여 저장한다.
   지도 편집 이후에는 **최신 지도 버전 확인**으로 적용할 버전을 명시적으로 바꿀 수 있다.
6. 실제 동기화는 `recorded` + `synchronized`, 카메라별 첫 프레임 시각·오프셋·시각 확인 근거가 필요하다.
   **공통 시간축 조회** 후 공통 시점에서 재생한다. 촬영 범위 밖과 길이 미확인은 관측 누락이다.
   개별 영상은 독립 재생한다. `scenario`는 가상 시연으로 표시하며 실제 동시 관측으로 합산하지 않는다.
7. **학습용 CSV 다운로드**는 저장된 세션 버전을 기준으로 생성한다. 기본 5초, 1/5/10/30/60초를 지원한다.
   카메라 ID 또는 구역 ID로 필터링할 수 있다. 비우면 세션 통합 long-format이다.
   **스키마 JSON 다운로드**에 입력 자료형·누락·시간 의미·분할 규칙이 포함된다.

## API와 DB

신규 migration `20261117_09`는 `capture_session_revisions`, `20261117_10`은 `capture_video_venues`를 추가한다.
기존 migration을 수정하지 않는다. 세션은 지도 버전에 고정되고 수정은 새 버전으로 추가한다.
영상 소유 장소는 DB 기본키로 보호하여 동시 요청에서도 다른 장소로 중복 등록하지 못한다.
기존 영상의 촬영 시각이나 원본 CSV는 덮어쓰지 않는다.

| API | 용도 |
|---|---|
| GET/POST `/api/capture/venues` | 장소 목록/등록 |
| GET `/api/capture/venues/{venue}/jobs` | 해당 장소의 지도·세션에 연결된 분석만 조회 |
| GET `/api/capture/venues/{venue}/sources` | 해당 장소/미배정 영상과 완료 분석·ROI 목록 |
| GET/POST `/api/capture/venues/{venue}/sessions` | 세션 목록/등록 |
| GET `/api/capture/venues/{venue}/sessions/{session}` | 최신 세션 상세 |
| POST `.../{session}/revisions` | `base_revision`을 확인하여 이력 추가 |
| GET `.../{session}/timeline` | 공통 시간 범위·카메라별 누락 상태 |
| GET `.../{session}/dataset.csv?interval=5&camera_id=...&zone_id=...` | DB에 저장된 관측으로 CSV 생성 |
| POST `.../{session}/concentration` | 고정된 지도·세션·촬영 시각으로 기존 조건부 엔진 호출 |
| GET `/api/capture/schema` | 세션 및 학습 데이터 스키마 |
| GET `/api/capture/upload-policy` | 현재 업로드 정책 |
| POST `/api/capture/videos/upload?filename=...` | 원본 파일 body 업로드 |

세션 저장 본문: `base_revision`, `venue_revision`, `data` (`/api/capture/schema` 참고).
집중 추정 본문: `session_revision`, `offset_seconds`, 선택적 `target_zone_id`.
영상/분석/ROI가 지도에 보정된 것과 다르면 추정을 차단한다. 다른 영상으로 경계 보정을 임의 전이하지 않는다.
관제 지도 `target_policies`는 구역 ID별 정책이며, `center_zone_id`는 현재 선택한 기본 대상이다.
대상을 바꾸어도 다른 대상의 통로·정책은 보존된다. 기존 단일 중앙 구역 설정도 호환된다.
추정 API의 `target_zone_id`로 대상을 지정할 수 있다. 여러 대상의 값을 합쳐 전체 인원으로 표시하지 않는다.

## 학습 데이터 의미와 제한

- 한 행은 카메라·분석 당시 ROI·완료된 시간 구간이다. 카메라 수가 늘어도 컬럼은 변하지 않는다.
- `video_offset_ms`와 `timestamp`는 집계 **종료** 시점이다. 절대 촬영 시각이 검증되지 않으면 timestamp는 null이다.
- 카운트는 완전한 1초 관측들의 평균, 유입·유출은 합계이다. 누락/중복 초가 있으면 해당 구간 값은 null이다.
- `count_change`와 최대 5개 구간의 `rolling_mean`은 연속된 과거 완료 구간만 이용한다. 결측을 가로질러 계산하지 않는다.
- motion은 기존 Flow 값과 저신뢰 정책을 재사용한다. 저신뢰·정보 부재 시 null이다.
- `direction_count`, `reverse_direction_count`는 대상별 경계 보정과 트랙 검증을 갖춘 추출기 연결 전까지 null이다.
- `bottleneck_score`는 전체 영상 정규화로 미래 정보가 포함될 수 있는 기존 사후 점수를 그대로 학습 입력에 넣지 않기 위해 null이다.
- 구역 필터는 해당 구역에 연결된 카메라 행을 제공한다. 겹치는 카메라 인원을 자동 합산하거나 중복 제거하지 않는다.
- 실제 시각이 있는 행은 세션 범위를 벗어나면 제외한다. 계획 세션의 상대 시간은 실제 촬영 시각으로 바꾸지 않는다.
- 현재는 특징 데이터이며 미래 정답/성능 지표는 생성하지 않는다. 날짜·세션 단위로 먼저 학습/검증/테스트를 분리한다.
- 최대 250,000행 및 CSV 텍스트 16Mi 문자로 메모리를 제한한다. 초과 시 카메라/구역으로 나누어 추출한다.
  한 세션 최대 7일, 한 카메라당 활성 파일 하나이다. 연속 분할 파일 자동 접합은 미구현이다.

## 장시간 영상

기존 200MiB multipart 경로는 유지한다. 신규 경로는 raw body를 디스크로 기록하여 multipart 전체 버퍼링을 피한다.
기본 2GiB, 환경 변수 `CAPTURE_MAX_UPLOAD_BYTES`로 조정(상한 8GiB), 저장 공간 1GiB를 남긴다.
클라이언트는 파일별 진행률을 표시하고 순차 업로드하며 요청 제한은 30분이다. 실패한 파일만 전체 재업로드한다.
완료된 파일은 보존한다. 실패한 요청이 새로 만든 파일만 정리한다. 기존 파일을 삭제하지 않는다.
OpenCV로 컨테이너 길이를 조회하며 전체 프레임을 분석하지 않는다. 길이를 확인할 수 없으면 null이다.
리버스 프록시의 body/timeout 제한은 별도 배포 설정이 필요하다.
기존 Worker 메모리·처리량, 64MiB 추적 CSV 및 프레임 인덱스 제한은 그대로이다.
**30분 이상 실제 영상의 분석 완료·메모리·재생 성능은 아직 미검증이다. 업로드 지원을 분석 성능 보장으로 해석하지 않는다.**

## Forecast 환경과 모델

서울 행정동 427개, 168시간 이력으로 1시간 후 생활인구를 예측하는 기존 모델과 영상 단기 집중 추정은 별개이다.
기존 서울 모델은 `population_forecast`의 별도 Python 프로세스 어댑터를 재사용한다.
`CROWD_FORECAST_PYTHON`을 독립 인터프리터의 절대 경로로 지정한다.
`requirements-forecast.txt`는 실제 import와 Parquet 입출력에 필요한 선언이며 **lock 파일이 아니다**.
팀원의 학습 당시 정확한 버전은 제공되지 않았으므로 임의로 고정하지 않는다.
전용 환경의 인터프리터로 `backend/scripts/check_forecast_runtime.py`를 실행하면 설치 상태만 조사한다.
이번 작업에서는 패키지 설치 및 기존 CPU/GPU 환경 변경, 모델 로드·재학습을 하지 않는다.

영상 모델은 기존 `ForecastContract`의 대상·구역·시간 범위·학습 단위·전처리·아티팩트 해시·환경·평가 증거를 받아 연결한다.
`validate_hybrid_compatibility`는 동일 대상·horizon·단위·입력 식별자·전처리의 계약만 허용한다.
실제 혼합은 시각 정렬과 검증된 가중치를 확보한 후 구현한다. 현재 Hybrid 예측을 생성하지 않는다.
팀원의 `video_pipeline.run_video_forecast`는 실행 중 학습과 보간/0 채움이 포함되어 있어 새 CSV 추출 시 자동 호출하지 않는다.
학습 데이터와 영상용 고정 모델이 준비되기 전까지 화면의 10/30/60초 값은 조건부 추세 추정이다.

## 실제 자료 확보 후

촬영 시각·카메라 위치·시야 중복·실제 이동 경계를 검증하고 독립 인원 정답을 확보한다.
장소·날짜를 분리한 평가, 역광/야간/가림/혼잡도별 성능, 장시간 Worker 부하와 복구를 검증한다.
구역별 용량·통로 이동 시간·인력 역할과 이동/배치 소요시간·운영 기준은 현장 근거를 받아 설정한다.
현재는 관리자 검토와 대응 이력을 지원하며 사고 확률이나 필요 인력 수를 자동 확정하지 않는다.
