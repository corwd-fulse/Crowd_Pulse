# 중앙 방향 흐름과 조건부 집중 추정

이번 기능은 기존 YOLO/ByteTrack/Optical Flow를 바꾸지 않고, 저장된 추적 리플레이와 분석 결과를 읽는다. `forecast/`의 팀원 모델은 로드하거나 학습하지 않는다.

## 운영 순서

1. 기존 대시보드에서 실제 평면도와 겹치지 않는 지도 구역을 등록한다.
2. 다중 카메라 패널에서 중앙 집결 구역을 선택하고 카메라를 추가한다. 카메라 수는 4대로 고정하지 않았으며 요청 자원 제한은 32대, 통로 64개다.
3. 각 카메라의 완료 분석 작업, 분석 당시 ROI, 담당 지도 구역, 실제 지도 위치·관측 범위·촬영 방향을 입력한다. 기본 위치는 미설정이며 임의로 표시하지 않는다. 기존 DB `cameras`에 연결하려면 해당 영상에 이미 등록된 ID만 지정한다. 영상 ID와 결과 fingerprint는 서버가 저장한다.
4. 통로의 출발 구역과 중앙 구역을 연결하고, 원본 영상에서 유한 경계선의 두 점과 중앙 측 기준점 하나를 지정한다. 영상 픽셀 좌표는 지도 좌표와 다르다. 촬영 방향 각도나 Optical Flow 각도를 지도 방향으로 자동 해석하지 않는다.
5. 경계의 실제 의미와 중복 배제 근거를 입력한다. 접근 경계와 중앙의 실제 출입 경계를 구분한다. 접근 경계의 도착률·이동 시간은 기본 미확보이며, 가정 또는 측정 기록이 있을 때만 입력한다.
6. 독립 영상은 합산하지 않는다. 실제 동기화는 각 영상 첫 프레임의 시간대 있는 촬영 시각·검증 표시·근거가 필요하다. 가상 시나리오에서는 오프셋으로 대응시킬 수 있지만 실제 동시 관측으로 표현하지 않는다. 테스트 분석을 실제 동시 관측으로 통합하지 않는다.
7. 지도 설정을 새 버전으로 저장한 뒤 영상을 정지하거나 원하는 시점으로 이동해 ‘현재 시점 조회’를 누른다. 재생 시각·설정이 바뀌면 조회 결과가 해제된다. 다른 카메라의 원본·YOLO·2D/3D는 작업별 링크로 확인한다. 서로 다른 영상 플레이어의 강제 동기 재생은 아직 제공하지 않는다.
8. 확인 담당자·현장 확인 상태·대응 검토·메모를 명시적으로 기록한다. 신고 참고 정보는 등록 주소·관측 시각·근거·연결 카메라를 정리할 뿐 외부로 전송하지 않는다.

## 경계 통과 정책

`app/services/concentration.py::gate_events()`는 기존 리플레이의 bbox 하단 중앙 좌표와 로컬 `track_id`를 이용한다. 경계선 길이 밖의 통과는 제외한다. 선에서 3픽셀 이내는 방향 판정을 보류하며, 반대 측 관측 2개가 연속 확인되면 통과 이벤트를 만든다. 시각은 두 번째 관측의 확인 시각으로 기록하고 경계 교차 시각을 보간하지 않는다.

ID 단절·중복 ID·교환 의심·불명 ID·ROI 겹침 진단을 재사용하며 카메라 간 ID를 이어 붙이지 않는다. `camera_id:job_id`로 출처를 구분한다. 확인된 통과는 실제 전체 이동의 하한이고 고유 방문자 수가 아니다. 단순 인원 증감이나 Optical Flow 각도만으로 통과를 만들지 않는다.

통합 전 동일 원본 해시/영상·ROI, 겹치는 집계 그룹, 같은 원본의 동일 통과 근거를 검사한다. 서로 다른 카메라의 중복 사람을 자동 재식별하는 기능은 없다. 통로의 공간적 독립성은 관리자 근거가 등록되어야 하며, 그 기록 자체가 현장 검증을 자동으로 보장하지는 않는다.

## 추정

기본 모델 버전은 `central-flow-constant-rate-v1`, 이력 창은 기본 30초이며 10~120초에서 설정한다. 예측은 10/30/60초만 제공하고 항상 흐름 유지 가정의 저신뢰 결과로 표시한다. 5분 예측은 지원하지 않는다.

- 중앙의 실제 출입 경계: 최근 확인 유입/유출 ÷ 이력 창 × horizon으로 조건부 흐름을 계산한다.
- 접근 경계: 등록된 도착 비율과 이동 시간을 사용해 이미 통과해 이동 중인 관측 코호트의 예상 도착분과 미래 통과분의 예상 도착분을 더한다. 이력은 이동 시간과 집계 창까지 포함해야 한다. 가정·측정·미확보를 결과에 보존한다. 접근 경계의 반대 통과는 중앙 유출로 차감하지 않는다.
- 중앙 총인원: 대표 카메라의 중앙 ROI 현재 인원, 전체 구역 관측 확인, 전체 중앙 출입 경계 관측 근거, 중복 배제·시간·추적 품질이 모두 충족될 때만 `max(0, 현재 인원 + 예상 유입 - 예상 유출)`을 제공한다.
- 위 조건이 없으면 중앙 총인원은 NULL이다. 흐름 관측이 가능하면 중앙 방향 통과 압력(회/분)을 제공하고, 도착률·이동 시간이 없으면 도착량도 NULL이다.

완료된 초·병목 창만 참고하며 추정 시각 이후 이벤트·인원을 사용하지 않는다. 기존 병목 점수는 기존 결측·저신뢰 정책에 따라 표시하는 사후 연구 지표이며 새 안전 점수로 재계산하지 않는다. 등록 임계값이 없으면 정상 판정을 만들지 않는다. 주의·경계·긴급 확인 필요는 운영 검토 상태이고 사고 확률이 아니다. 인력 수를 산출하지 않는다.

## 저장과 API

기존 `venue_revisions.configuration`에 `address`, `center_zone_id`, `integration_mode`, `cameras`, `corridors`, `concentration_policy`를 추가한다. 기존 구역·마커·ROI 매핑은 유지된다. 카메라별 원본 ID와 fingerprint, 분석 ROI snapshot을 서버가 저장하며 변경 시 새 버전을 추가한다. 영상/ROI 변경 시 UI는 경계·시계·중복 배제 확인을 해제한다.

신규 migration `20261117_08`은 다음 테이블만 추가한다.

| 테이블 | 내용 |
|---|---|
| `venue_concentration_runs` | 행사장·설정 버전 FK, 조회 기준 시각/오프셋, 결과·출처 snapshot, 생성 시각 |
| `venue_operator_events` | run FK, 담당자, 문제 구역, 현장 확인 상태, 대응 검토 종류, 메모, 서버 기록 시각 |

이력은 추가 방식으로 저장한다. 기존 관측 DB/CSV는 수정하지 않는다. 인증 기반 담당자 신원 검증과 보존 정책은 기존 프로젝트에 없으므로 별도 후속 기능이다.

| 메서드·경로 | 기능 |
|---|---|
| POST `/api/venues/{id}/revisions` | 기존 설정 API 확장, 카메라/경계/ROI/시각 검증 |
| POST `/api/venues/{id}/concentration/estimate` | 최신 저장 버전과 기준 시각으로 계산·새 run 저장 |
| POST `/api/venues/{id}/concentration/evaluate` | 해당 버전의 과거 시점 예측과 미래 ROI 관측 비교. 기존 데이터 변경 없음 |
| GET `/api/venues/{id}/concentration/runs` | 최근 30개 계산 이력 요약 |
| POST `/api/venues/{id}/operator-events` | 명시적 관리자 확인·메모 저장 |
| GET `/api/venues/{id}/operator-events` | 최근 50개 확인·메모 이력 |
| GET `/api/venues/forecast-contract/schema` | 팀원 모델 수신 계약 JSON Schema. 모델 로드 없음 |

추정 요청 형태:

```json
{"revision": 1, "offset_seconds": 30, "at": null}
```

실제 시각 동기화 모드에서는 `at`에 시간대가 포함된 공통 촬영 시각이 필요하다. 각 영상 오프셋은 그 시각에서 해당 영상 촬영 시작 시각을 빼서 구한다. 검증되지 않은 요청 시각은 실제 관측 시각으로 표시하지 않는다.

## 검증과 팀원 모델 교체

`evaluate_history()`는 각 horizon에 최대 50개 과거 기준점을 정하고 그 시점까지의 자료만으로 계산한 뒤 미래 중앙 ROI 인원과 비교한다. MAE/RMSE·표본 수·기준점·모드·모델 버전을 반환한다. 중앙 대표 관측이나 충분한 자료가 없으면 지표는 NULL이다. ROI 비교는 독립적인 현장 정답 검증과 다르며 가상 시나리오 수치를 실제 동시 카메라 성능으로 사용하면 안 된다.

팀원에게 다음을 받는다: 아티팩트와 SHA-256, 입력 컬럼, 예측 대상 종류, 대상 구역, horizon, 학습 단위와 카메라/구역 식별자, 최소 이력, 모델·Python·패키지 버전, 전처리 버전/코드, 검증 지표, 출력 예시.

`app/services/forecast_contract.py::ForecastContract`로 메타데이터를 검증하고 `validate_center_output()`으로 출력의 중앙 구역·horizon·유한 비음수 값·모델 버전을 확인한다. 행정동 또는 행사장 전체 인원을 중앙 인원으로 바꾸어 표시하는 것을 거부한다. 실행 어댑터는 `concentration.Estimator` 인터페이스로 추가할 수 있다. 현재는 스키마와 범위 검증만 구현했으며 실제 팀원 모델 로드·환경 구성·추론 연결은 하지 않았다.
