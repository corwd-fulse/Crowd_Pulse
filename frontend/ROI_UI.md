# 영상별 ROI 설정

영상 관리에서 영상을 선택하면 원본 해상도의 SVG 좌표계로 구역을 편집합니다. 영상과 오버레이는 같은 종횡비의 래퍼를 사용하므로 화면 축소, 세로 영상, 모바일에서도 레터박스 좌표를 저장하지 않습니다. 프레임이 바뀌어도 고정 ROI이며 전체 영상에서의 적합성은 사용자가 확인해야 합니다.

새 구역 그리기 → 이름 입력 → 클릭/터치로 점 추가 → 완료 버튼 또는 더블클릭 → 구역 선택/꼭짓점 드래그 → 저장 전 미리보기 → 후보 ROI 최초 저장 순서입니다. 폴리곤 자체 교차, 면적, 중복 꼭짓점/이름, 좌표 범위, 구역 포함/교차/경계 접촉을 차단합니다. 접한 경계도 보수적으로 금지하므로 구역 사이에 간격을 둡니다.

## API와 보존 정책

- GET `/api/videos/{id}/roi`: 기존 API 사용. 404는 미등록으로 처리하고 다른 조회 실패에서는 저장을 허용하지 않습니다.
- PUT `/api/videos/{id}/roi`: 원래 JSON 본문 그대로 사용하며 UI는 `If-None-Match: *`를 보냅니다. 백엔드가 영상 행 잠금 후 등록 여부를 확인하여 기존 ROI가 있으면 412를 반환합니다. 조건부 헤더가 없는 기존 클라이언트의 교체 계약은 변경하지 않았습니다.
- UI 저장은 항상 `status=candidate`, `approved_for_analysis=false`입니다. 자동 승인 기능은 없습니다.
- 기존 ROI는 편집/삭제하더라도 서버에서 교체하지 않습니다. 수정본은 후보 JSON으로 내보내며 원본 승인 상태를 상속하지 않습니다. 최초 저장 버튼은 비활성화됩니다. 수정본의 영구 버전 저장에는 별도의 append-only ROI revision API/모델이 필요합니다.
- 운영 요청은 현재 영상의 저장된 승인 ROI이고 미완성/미저장 변경이나 해상도 불일치가 없을 때만 활성화됩니다. 테스트 모드는 후보 ROI도 허용하지만 API `ALLOW_TEST_ANALYSIS`와 Worker `--allow-test-analysis` 정책을 그대로 적용하며 403 오류를 표시합니다. 테스트 허용 설정을 UI에서 변경하지 않습니다.
- 승인 전용 API/권한 체계는 현재 없으며 UI에 승인 버튼을 추가하지 않았습니다. 기존 PUT은 승인 스냅샷도 받으므로 운영 배포 전에 서버 권한 통제/감사/버전 정책을 별도로 설계해야 합니다.
